## Method (D-014)

- **Builds:** each candidate is a detached clone at its exact head, built in
  Release with the same CMake invocation. An unmodified base clone is the
  control. It reproduced the frozen baseline exactly (0 changed cases), and
  its `pycdc` is byte-identical to the baseline binary (sha256
  `8c0e1d26…`).
- **Corpora:**
  - `features`: 73 authored fixtures, up to behavior.
  - `upstream-inputs`: compiled and decompiled only.
  - upstream's token suite, run in the sandbox.
  - Each PR's own test inputs, compiled and decompiled only for 3.13 and
    3.14, never executed.
- **Isolation:** candidate binaries and recovered programs ran only in the
  harness sandbox.

## Code quality and overlap

**Overlap:**
- Of the fixed feature cases, 30 are fixed by both PRs, 39 only by #616 and
  12 only by #617.
- In `upstream-inputs`, everything #617 fixes is also fixed by #616.
- The PRs implement the same 3.13 `CALL`/`MAKE_FUNCTION` stack conventions
  independently and differently. Merging both would conflict throughout
  `ASTree.cpp`.

**PR #616:**
- One commit mixes:
  - the 3.14 decoding layer;
  - pycdas jump-offset changes for 3.13;
  - 3.9+ loop recognition through bytecode look-behind probes (a new
    `PycBuffer::setPos`);
  - 3.13/3.14 try/finally/continue handling;
  - changes that alter 3.9/3.10 output.
- It cannot be reviewed or adopted piecemeal from upstream's history.
- It changes behavior on versions it does not target: 3.10–3.12 gain 61 new
  silent mismatches.
- Three of #616's unmarked semantic errors are confirmed on authored probes
  (`REVIEW_NOTES.md`, `probes/`):
  - `x ^= y` becomes `x = x[y]` on 3.11/3.12 (a wrong `BINARY_OP 25` gate);
  - a generator's `yield`s are dropped on every version;
  - `except E: x = 1` becomes `except E as x:`.
- A read-only structural review is in `REVIEW_NOTES.md` (Opus sub-agent, not
  an independent review).

**PR #617:**
- Smaller and mostly version-gated (3.13+ or 3.14+).
- Unsupported shapes throw `std::runtime_error`, and pycdc then exits
  nonzero.
- Function defaults and keyword-only defaults are reconstructed from
  `SET_FUNCTION_ATTRIBUTE`: `functions/defaults`, `lambdas` and
  `exit_handlers` pass on 3.13/3.14 only with #617.
- Heuristics that read ahead in the bytecode stream:
  - the short-circuit expression probe;
  - collapsing consecutive `STORE_FAST`s into tuple assignments.
- Changes that affect every version:
  - the fallthrough-return probe in the `RETURN_VALUE` handler;
  - `POP_BLOCK` at the root is silently ignored;
  - a circular reference in the printer now throws instead of warning.
- It rewrites decorators and non-lambda function arguments as
  `name = function` stored before the call (`call_argument`). The function,
  including its default values, is then created before the decorator
  expression is evaluated, and the name is briefly bound to the undecorated
  function. Both differ from the source's evaluation order. This was
  confirmed on an authored probe (`REVIEW_NOTES.md`); no corpus fixture
  covers it.

## Integration decision (D-015)

**Adopted:** the 3.14 decoding layer only, as three small commits on
`bootstrap` with co-author attribution.

1. `200a4cd`: slice constants (`TYPE_SLICE`): loader and pycdas listing from
   #596, rendering from #616.
2. `27ef3c6`: magic 3627 and the 3.14 opcode table, verbatim from #616
   (identical to #617 apart from #617's aliases).
   - Separate internal opcodes for 3.14's changed `CALL_FUNCTION_EX` and
     `END_ASYNC_FOR`.
   - pycdas operand display matching `dis` 3.14.9, with #616's two display
     errors corrected.
3. `d0452df`, `332b5b7`: harness tooling for this evaluation (not production
   code).

**Rejected for now:**
- Both PRs' AST builder changes, for 3.13/3.14 as well as their side effects
  on older versions.
- **Reasons:**
  - many new silent mismatches (162 and 60);
  - new crashes and hangs;
  - #616's size and mixing;
  - behavior changes on 3.10–3.12 that neither PR targets.
- In Parts 5–7 they are **reference implementations** to consult, with
  attribution if any part is adopted:
  - #617 for `MAKE_FUNCTION`/`SET_FUNCTION_ATTRIBUTE`, `CALL`/`CALL_KW`
    stack order, `CALL_FUNCTION_EX`, `DICT_MERGE`, `LOAD_SMALL_INT` and the
    `__classdict__` handling;
  - #616 for loop and exception-table structure.
- Every adoption must follow those parts' process: a minimal failing
  regression first, then the smallest justified change.

**Integrated result (`27ef3c6`, `results/integrated.json.gz`):**
- vs baseline: regression 0, fixed 15, missing coverage 0, harness error 0,
  corpus drift 0. All 369 `failure_changed` cases are 3.14 cases that moved
  from load to decompile.
- No new crash and no new silent failure in any suite.
- 3.10–3.13 are identical to the baseline.
- 3.14:
  - 219/219 feature cases load and disassemble, then stop explicitly at
    decompile: 168 at `MAKE_FUNCTION`, 48 at `LOAD_SMALL_INT`, 3 at
    `MAKE_CELL`. Upstream inputs also stop at `POP_ITER`, `LOAD_SPECIAL`,
    `BINARY_OP 26` and others.
  - 15 upstream inputs now recompile.
- Debug build: identical results.
- Upstream token suite: 191/39, unchanged per file.
- Controls: 0 unexpected.
- `gate --part 4`: 429/429 required cases reach disassemble, but the gate is
  **NOT PASSED**. Its four manual-evidence items now count as problems; they
  used to be printed as notes beside "GATE PASSED".
  - Part 4's manual items are **not** done: semantic pycdas-versus-`dis`
    comparison, hash-based headers, unsupported-format and malformed-input
    behavior.
- `gate --part 5..7`: 0/162, 0/114, 0/153.

## Reproduction check

`reproduce.sh` was run end to end into a fresh directory
(`build/part3-repro`, exit 0) and compared with these files.

- **Identical case for case:** base, PR #617 and the integrated build; the
  contributor-input tables; every build's upstream token suite.
- **Integrated build:** one pre-existing upstream crash
  (`exceptions/with_statements`, 3.10 `-O1`) died with SIGBUS instead of
  SIGSEGV. A wild memory access gives either signal depending on the
  address.
- **PR #616:**
  - `loops/nested_exits` crashed with SIGSEGV in one run and with SIGBUS, or
    an uncaught C++ `std::vector` exception, in the other. That
    nondeterminism is consistent with memory corruption. Its new-tool-crash
    count is therefore 9 in this report and 8 in the reproduction.
  - Timeout causes record the wall-clock time and differ in the decimals.
- **`compare` now ignores this noise.** Run-to-run differences in the crash
  signal, the timeout duration and pycdc's internal opcode numbers in
  "Unsupported opcode" causes no longer count as `failure_changed`. The
  opcode numbers shift whenever an opcode is added, as the 3.14 entries do.
- **Result:**
  - the integrated build vs the reproduction: 0 changes;
  - PR #616 vs its reproduction: 1 genuine change, the `std::vector`
    exception above.

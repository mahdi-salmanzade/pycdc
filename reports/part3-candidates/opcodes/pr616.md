# Opcode coverage audit

Generated by `harness/tools/opcode_coverage.py`. CPython tables come from each pinned interpreter's `dis.opmap` (values < 256); "used" counts raw opcodes in the compiled feature corpus (all optimization levels). "handled" means ASTree.cpp has a `case Pyc::<name>` label; an unhandled opcode reaches the switch default and is reported as "Unsupported opcode". Static cross-check only; whether a handled opcode is decompiled correctly is measured by the differential harness, not here.

## Caveats

- `EXTENDED_ARG`: `bc_next` folds one prefix into the following instruction, so the switch only sees a second consecutive prefix. "Unhandled" overstates its gap.
- `CACHE`: decoded as its own instruction and handled as a no-op in the switch.
- Some opcodes are consumed by look-ahead inside other cases (extra `bc_next` calls); this static check cannot see that.
